# Авторазбор и чистый чат · 3.3

Отправь текст или поддерживаемый файл из главного меню. Бот сначала сохраняет исходник, затем ИИ выбирает библиотеку, дела или оба раздела. Рецепты, инструкции и чужие примеры не должны становиться личными задачами без явного намерения пользователя. Это вероятностная классификация; результат нужно проверять.

- В библиотеке: понятное название, выжимка, исходник и извлечённый текст.
- В делах: до шести действий, приблизительное полное время активной работы, объяснение допущения и ссылка на исходник. Оценка от 1 до 1440 минут; это не длительность таймера фокуса. Долгое ожидание в оценку не входит.
- Смешанный материал: справка в библиотеке плюс связанные дела.
- «Вернуть в библиотеку» удаляет только неизменённые, не начатые дела этой партии. Отредактированные, выполненные и начатые дела сохраняются. Исходник остаётся всегда.
- В карточке дела можно изменить название и время, включая ввод своего числа минут.

Исходник материала, отправленного только в дела, скрыт из обычного списка библиотеки, но открывается из дела, находится поиском и входит в экспорт. Выбранные проекты, «Работа рядом», мастера создания задач, поиска и ИИ-диалог сохраняют свой явно выбранный режим. Авторазбор их не перенаправляет.

Настройки → «Авторазбор»: включён по умолчанию, если настроен Yandex AI. Отправляется только новый материал, без чужих данных и истории ИИ-диалога. Выключение прекращает создание результатов ещё работающих заданий; уже отправленный провайдеру запрос отозвать нельзя.

Текст, PDF с текстовым слоем и TXT/MD требуют один запрос DeepSeek. JPEG/PNG и короткий Ogg Opus — до двух запросов: OCR/SpeechKit и разбор. Действуют общие дневные квоты бота. Ссылки не открываются: ИИ видит адрес и подпись. Форматы и ограничения распознавания — в RECOGNITION.md. Исходное изображение не анализируется как визуальная сцена: ИИ обрабатывает извлечённый OCR-текст.

Авторазбор работает в фоне, максимум два задания и одно на пользователя одновременно. Результат сохраняется в SQLite. Если пользователь уже перешёл дальше, текущая панель не заменяется; результат доступен из карточки материала. Ошибка API, квоты или неподдерживаемый файл оставляют исходник в библиотеке. Незавершённый платный запрос после перезапуска автоматически не повторяется: доступна кнопка повтора. Ещё не начатые задания продолжаются. Дела и результат записываются одной транзакцией, повтор завершения не создаёт дубликатов.

## Хранение и удаление из чата

Новые входящие вложения скачиваются в `data/files/<owner>/` (или `files` рядом с настроенной базой). Telegram file ID тоже сохраняется. До удаления сообщения проверяются завершённая запись материала, размер и SHA-256 локальной копии. Рабочий черновик без подтверждения не удаляется. Ошибка скачивания, повреждённый файл, превышение размера или отсутствие места оставляют входящее сообщение.

Cloud Bot API позволяет скачать до 20 МБ; локальный архив ограничен примерно 512 МБ на пользователя и 5 ГБ на бот с резервом для текущих загрузок. Файлы крупнее сохраняют Telegram-ссылку и остаются в чате. Для распознавания действуют более низкие пределы. Архив не является отдельной резервной копией диска. Для резервирования нужно копировать `data/files` вместе с согласованной резервной копией SQLite. JSON-экспорт версии 7 содержит метаданные файлов и авторазбор, но не байты вложений.

Запрошенные оригиналы и экспорты отправляются отдельными сообщениями и ставятся в устойчивую очередь удаления через 3600 секунд. После перезапуска очередь продолжается. Удаляется только сообщение с выданной копией, сами материалы и локальные файлы сохраняются. Очистка работает, пока бот включён и доступен Telegram. Удаление записи материала пока не уничтожает байты локального архива: к ним закрывается доступ через бот; автоматический сбор неиспользуемых файлов не добавлен.

Обычный интерфейс занимает одну панель бота и последнее текстовое сообщение пользователя. Предыдущий пользовательский текст удаляется при следующем обработанном сообщении. Вложения до завершения сохранения и выданные файлы до истечения часа — временные исключения. Старую неотслеживаемую историю бот не перебирает. Telegram ограничивает удаление сообщений возрастом 48 часов, поэтому после долгого простоя отдельные сообщения могут остаться.

Источники ограничений: [Telegram deleteMessage](https://core.telegram.org/bots/api#deletemessage), [Telegram getFile](https://core.telegram.org/bots/api#getfile).

## Проверка

Проверены изоляция пользователей, атомарность задач, повтор завершения, отмена с сохранением правок, восстановление после перезапуска, ошибки квот, размер/целостность файлов, источник до удаления, часовая очередь и обновление панели при уведомлениях. Через действующий Yandex API на трёх вымышленных примерах проверены маршруты «дела», «библиотека» и «смешанный», включая сохранение явно указанной длительности. Личные материалы в проверке не использовались.
