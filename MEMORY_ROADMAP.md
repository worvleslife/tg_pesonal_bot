# Личная память: первый выпуск и дальнейшая реализация

Версия 3.1 · 2 октября 2026. Основано на предложенных владельцем сценариях. Весь список ещё не реализован. Следующий слой — [вложения, оригиналы и разбор изображений](RECOGNITION.md).

## Что можно сделать сейчас

1. `/projects` → создать проект, указать цель. Подходит для учёбы, поездки, выставки, ремонта или конкретного устройства.
2. В карточке материала библиотеки или «Работа рядом» → «Связать с проектом». Либо открыть проект и прислать файл прямо туда, в том числе через «Добавить файл». Создаётся карточка с названием и собственной Telegram-ссылкой на оригинальный файл. Удаление библиотечного источника больше не лишает проект файла. Старые связи дополняются при обновлении, если исходный материал ещё существует. Изображения можно обработать цепочкой OCR → выжимка ИИ с названием, важными сведениями и цитатами. Полный OCR-текст хранится отдельно; сохранение выжимки требует подтверждения.
3. В проекте создать наблюдение, сведения из инструкции, решение с объяснением, идею, открытый вопрос, результат или предположение. Тип задаёт пользователь; это не автоматическая проверка достоверности.
4. Создать случай: объект → симптомы → проверки → действия → результат. Сохранить результат позднее кнопкой «Что в итоге помогло?». Бот отдельно указывает, что последовательность события и действия не доказывает причинную связь.
5. Из записи создать дело. Оно получает ссылку на запись и связь с проектом. Когда дело по случаю впервые отмечено выполненным, бот предлагает записать результат. Дополнительное напоминание можно создать из записи через существующий мастер времени.
6. `/memory камера пропадала` ищет по библиотеке, рабочим материалам, подтверждённым результатам распознавания и проектным записям. Возвращаются выдержки, типы сведений, даты и кнопки оригиналов. Это поиск по словам с простой обработкой русских окончаний, а не семантический поиск. Синонимы и значение фразы «перед командировкой» не понимаются. Неподтверждённые черновики и полный исходный OCR под ИИ-выжимкой в поиск не включаются. «Похожие случаи» не оценивает совпадение условий в процентах.
7. «Верни меня в проект выставки» открывает подходящий проект либо предлагает уточнение. В нём — цель, последние решения, вопросы, случаи, идеи и до пяти связанных дел. Если у первого открытого дела есть точка продолжения, показывается её следующий шаг. Сводка опирается на последние 1000 записей; полный список доступен по страницам.
8. При исправлении текстовой записи видны изменённые строки перед сохранением; прошлые версии доступны в истории. Для случая обновляется результат с сохранением прежних полей. Изменение оригинального материала не обновляет запись проекта автоматически: это сохранённая копия на момент привязки.
9. «Памятка» показывает состав выгрузки. Markdown-файл с целью и до 1000 текущих записей отправляется только самому пользователю. История версий не входит в памятку, но входит в личный JSON-экспорт. Файл можно отредактировать перед самостоятельной передачей. Бот никому его не пересылает.
10. «У меня есть 20 минут» подбирает дело по пользовательской оценке длительности. Распознаются целые значения от 1 до 180 минут. Это не учёт местоположения, энергии или доступного оборудования.

Фразы работают из обычного режима и экранов просмотра дел/проектов; во время ИИ-диалога и другого пошагового ввода текст остаётся в текущем сценарии.

## Почему распознавание — отдельная часть

Текущий ИИ-диалог работает через текстовый API Yandex AI Studio. Для распознавания речи и OCR у API-ключей есть отдельные области действия. Наличие рабочего ключа для диалога не подтверждает эти права. [Документация областей API-ключей](https://github.com/yandex-cloud/docs/blob/master/en/iam/concepts/authorization/api-key.md).

Vision OCR принимает JPEG, PNG и PDF; SpeechKit имеет отдельные ограничения длительности и размера, зависящие от режима API. Поэтому кнопка «прочитать что угодно» не должна скрывать частичное извлечение, ошибки или расходы. [Vision OCR](https://aistudio.yandex.ru/en/docs/vision/ocr/api-ref/TextRecognition/recognize), [SpeechKit](https://yandex.cloud/ru-kz/docs/speechkit/stt/api/request-api).

В версии 3.1 OCR и SpeechKit подключены. Доступ проверен искусственными данными; OCR и последующий ИИ-разбор успешно прошли проверку содержания, SpeechKit — проверку доступа на тишине. Настоящая речь в проверке не использовалась. Распознавание запускается явно, обрабатывается в фоне и имеет лимиты; после перезапуска повтор платного запроса выполняется только вручную. Сайты, длинное аудио и многостраничные сканы ещё не обрабатываются. Все ограничения — в RECOGNITION.md.

## Постоянные правила

- Все чтения и изменения привязаны к Telegram ID. Проекты и записи другого пользователя недоступны даже при подставленном ID кнопки.
- Оригинал, запись пользователя и предположение различаются. Уверенность поиска нельзя изображать вероятностью истинности.
- Исправление создаёт версию; устаревшее подтверждение не перезаписывает более новую запись.
- Удаление проекта/записи требует подтверждения и удаляет соответствующую историю. Оригинальные материалы и дела остаются.
- Собственный экспорт версии 7 содержит проекты, записи, версии, связи, ссылки на файлы проектов и распознавание. Самих байтов оригиналов в JSON нет. У оператора по-прежнему есть физический доступ к общей SQLite-базе; изоляция действует между пользователями бота.
- Главное меню остаётся из шести кнопок. Новые сценарии находятся внутри материалов и «Ещё».
