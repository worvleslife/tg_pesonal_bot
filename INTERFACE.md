# Интерфейс без лишних сообщений · 3.2 · 3 октября 2026

## Реализовано

Основной интерфейс — одно сообщение с inline-кнопками. Меню, проекты, материалы, дела, учёба, настройки, мастера ввода и экраны распознавания обновляют его через `editMessageText`. Номер панели хранится отдельно для каждого пользователя в SQLite и переживает перезапуск.

При первом открытии убирается старая клавиатура под строкой ввода; шесть основных кнопок появляются под самой панелью. Кнопки разделов не отправляют в чат текст вроде «Мои материалы». Команды и старые текстовые названия кнопок продолжают работать.

`/start` переносит панель к концу чата: создаёт новую и пытается удалить прежнее отслеживаемое сообщение панели. Telegram может запретить удаление старого сообщения; тогда оно останется в истории, а активной будет новая панель. Бот не перебирает историю и не удаляет пользовательские сообщения, файлы, напоминания или старые сообщения прежних версий.

Если панель удалена вручную или больше не редактируется, следующее действие создаст новую. Обычный сетевой сбой или ограничение частоты запросов не приводит к созданию дубликатов. Ответ Telegram «сообщение не изменилось» считается успешным обновлением.

Длинный текст отображается страницами в той же панели. При автоматическом разбиении слишком длинного форматированного экрана используется обычный текст без HTML-оформления; само содержание сохраняется. Страницы кешируются до смены экрана или перезапуска. Устаревшая кнопка предложит открыть материал заново. Листание не сбрасывает незавершённый ввод.

Фоновое распознавание может заменить экран ожидания только если пользователь ещё не перешёл дальше. После перехода в другой раздел готовый результат сохраняется в карточке файла, а текущий экран остаётся на месте. Доступна кнопка проверки статуса и открытия результата. ИИ-диалог сохраняет отдельное сообщение на каждый ответ; длинный ответ по-прежнему листается внутри одного сообщения.

Отдельными остаются:

- входящие сообщения и вложения пользователя;
- запрошенные оригиналы файлов и экспорты;
- напоминания, сводки и завершения фокуса;
- ответы ИИ, чтобы история разговора оставалась читаемой.

Это одна **панель управления**, а не удаление всей переписки и не Mini App. Общая блокировка данных и проверки владельца сохраняются; панель никогда не получает чужой `message_id` из кнопок.

## Следующий вариант: Telegram Mini App

Для приложения предлагаются четыре вкладки: «Сегодня», «Проекты», «Материалы», «Ассистент». Внутри проекта — карточки файлов с выжимкой, поиск, дела и история; ввод и просмотр происходят на отдельных экранах приложения. Напоминания продолжает отправлять бот в чат.

Для работающего Mini App нужен публичный HTTPS-адрес интерфейса и серверный API. Локальный `localhost` на компьютере оператора не обеспечивает доступ с телефона других пользователей. Внешний адрес и хостинг в этом выпуске не подключались.

На сервере необходимо проверять подпись и свежесть Telegram `initData`; доверять `initDataUnsafe` или присланному браузером user ID нельзя. Все запросы должны использовать Telegram ID из проверенной сессии и существующие проверки владельца. Токен бота и ключ Yandex остаются на сервере. Доступ к оригиналам выдаётся только после проверки владельца, без раскрытия Telegram URL с токеном бота. Для изменений нужны короткие сессии, защита повторного выполнения и тот же предпросмотр важных действий.

Существующие модули хранения и сценарии можно использовать через новый API, но сама браузерная оболочка, серверная авторизация и развёртывание ещё не реализованы. Одного добавления кнопки Web App недостаточно для безопасного доступа к личной базе.

Источники: [редактирование сообщений Telegram](https://core.telegram.org/bots/api#editmessagetext), [Telegram Mini Apps и проверка initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).
